## Установка одной командой

Review-сборка находится в `fix/awg-warp-safe-persistence`: [Draft PR #1](https://github.com/redoxprison-pixel/amnezia-warp-fix/pull/1). `main` пока содержит старую 6.60. Прежняя ссылка с `/main/govpn.sh` работает, но до объединения PR скачивает старый код. Main и production VPS в процессе разработки не меняются.

Для Linux с Bash 4+, Python 3.8+, curl, flock и root/sudo. Меню ориентировано на Debian/Ubuntu; для AWG требуются Docker и установленная Amnezia. Сначала просмотрите [install.sh](install.sh) и исходники из доверенной ветки. Затем:

```bash
curl -fsSL https://raw.githubusercontent.com/redoxprison-pixel/amnezia-warp-fix/refs/heads/fix/awg-warp-safe-persistence/install.sh | sudo bash
```

Если уже работаете от root, замените `sudo bash` на `bash`. Установщик проверяет Bash и три встроенных Python модуля, делает приватную резервную копию прежнего скрипта, блокирует одновременное обновление и атомарно устанавливает `/usr/local/bin/govpn`. После этого открывается меню. Это выполнение кода из доверенного репозитория, не криптографическая подпись поставки. Для установки без запуска меню используйте `sudo bash -s -- --no-run` справа от `|`.

Проверка версии: `/usr/local/bin/govpn version`. Старый кеш больше не выдается за новое обновление. Запуск: `sudo /usr/local/bin/govpn`. Сама установка файла не включает WARP. Полное меню выполняет подготовку системы, поэтому для простого просмотра версии используйте `version`.

Обновить уже установленную review-сборку:

```bash
sudo /usr/local/bin/govpn update
```

Обновление через меню **4 → 2**; команда CLI осталась прежней. Старый updater с источником `main` не видит Draft PR: для перехода используйте установщик выше. До отдельного выпуска в main review-ветка должна существовать; автоматического скачивания старого main при ее недоступности нет.

## Главное меню

- **1 - Клиенты**: имя, IP, последний handshake, выбранный маршрут; профиль/QR, подпись и восстановление доступа в одной карточке. При combo сначала выбирается Amnezia или 3X-UI.
- **2 - WARP**: автоматическое подключение, восстановление и отключение. Профиль используется повторно без ручного управления файлами.
- **3 - Диагностика**: один общий тест VPS, DNS/HTTPS, AWG, WARP, маршрутов и IPv6 с этапами и итогом; он не заменяет проверку на устройстве клиента.
- **4 - Обслуживание**: backup/restore, обновления, restart, подготовка резервного SSH через **3**.
- **5 - Дополнительно**: Telegram MTProto, сеть/каскады, домены/SSL, компоненты и опциональные инструменты 3X-UI.

Отдельный главный пункт «Клиенты → WARP» убран. В карточке **1 → клиент → 2** выбирается VPS/WARP; массовое изменение находится в **1 → r**. Enter возвращает назад (в главном меню - выход), а в списках клиентов обновляет данные. Цвета разделяют заголовки, номера, подписи и результаты. Нумерация в основных разделах идет подряд и связана с действиями одним массивом. Старые цифровые shortcuts убраны, чтобы один номер не имел двух смыслов. В режиме Amnezia восстановление AWG находится под 6. В других режимах номера зависят от доступных действий.

## Имена и сохраненные профили

Имена берутся из Amnezia clientsTable и связываются с peer по публичному ключу. Можно задать подпись GoVPN через **1 → клиент → 3**, не меняя таблицу приложения. Host labels хранятся приватно в `/etc/govpn/client-names` и следуют за ключом, не за переиспользованным IP.

Приватный ключ существующего клиента нельзя восстановить из публичного. При отсутствии сохраненной копии карточка предлагает способы восстановления вместо обычной кнопки экспорта, которая всегда завершается ошибкой. Экспортируйте обычный `.conf` с устройства или найдите доверенный backup, сохраните файл на VPS с правами 600 и используйте **1 → клиент → 4**. Проверяются IP, публичный ключ клиента, серверный ключ и PSK. Исполняемые hooks не принимаются. Повторная выдача использует ту же проверку; работа сети/Endpoint этим не подтверждается.

Профили хранятся с правами 600 в `/etc/govpn/client-profiles/<контейнер>` под идентификатором публичного ключа. Legacy `/etc/govpn/awg_clients/<IP>.conf` также проверяется перед выдачей. Широкого поиска по серверным .conf нет. Если устройство и копии потеряны, создайте новый доступ в Amnezia, проверьте его и отдельно отзовите старый. GoVPN не меняет ключ рабочего peer автоматически.

Во время настройки WARP видны текущий этап и лимиты ожидания, в конце - длительность и результат. Диагностика: **3 → 1**.

## WARP на новом сервере

Откройте **2**: мастер покажет текущий этап. Если профиля нет, первое действие предложит подключить WARP. Мастер сам создаст отдельный профиль через wgcf 2.3.1, если сохраненной настройки нет; повторное включение использует ее автоматически. Ручной импорт убран из обычного меню, технический CLI для восстановления остается. Регистрация требует принятия условий Cloudflare и явного списка клиентов. Существующие account/profile при переустановке не удаляются и не перерегистрируются. WGCF release assets закреплены SHA256; реальные регистрация и handshake могут быть отклонены Cloudflare и не выполнялись в тестах.

В AWG контейнере `wg` иногда является `amneziawg-tools`. GoVPN проверяет обычные WireGuard binaries; если их нет, установка извлекает отдельные `wg`/`wg-quick` из доверенных пакетов дистрибутива. Команды AWG не заменяются. Отдельные binaries сохраняются на хосте в `/etc/amnezia-warp/<контейнер>/native-tools` и включаются в runtime для restart/recreate. Первая установка требует работающего контейнера, kernel WireGuard и NET_ADMIN. Для recreate необходима остановленная фаза, см. runbook.

Профиль и positive selection IPv4 /32 хранятся в `/etc/amnezia-warp/<контейнер>/state.json` с правами 600. При включенном managed WARP весь IPv6 AWG блокируется. Для выбранного клиента нужен внешний IPv4 DNS в его профиле (например, `1.1.1.1`): локальный DNS запрещен защитными правилами. Профиль на телефоне скрипт не редактирует. Split tunnel и IPv6 вне VPN проверяются на устройстве.

WARP не является средством гарантированной смены страны и не обещает работу Gemini. Если через обычный выход VPS Gemini работает, оставьте клиенту маршрут VPS. Плюсы, недостатки и проверка описаны в [Gemini/WARP](docs/gemini.md).

## Разработка и проверки

Скрипт самодостаточен. Редактируйте `lib/awg_warp.py`, `lib/awg_clients.py` и `lib/diagnostics.py`, затем обновляйте встроенные копии:

```bash
python3 tools/bundle.py
python3 tools/catalog_functions.py
python3 -m unittest discover -s tests -v
python3 tools/bundle.py --check
python3 tools/catalog_functions.py --check
bash -n govpn.sh
bash -n install.sh
```

Изолированные Linux проверки: `python3 tests/docker/run_update.py` и `python3 tests/docker/run.py`. Отдельный `python3 tests/docker/run_native.py` использует сеть только для доверенных пакетов Alpine (или Ubuntu с `--debian`), затем отключает ее и проверяет приватный wg-quick. Production VPS не используется. Ни эти тесты, ни общий статический каталог не подтверждают все сторонние services и доступность Gemini.

Backups включают host WARP state/tools, labels и сохраненные клиентские профили. Legacy restore не является полным автоматическим disaster recovery; ограничения перечислены в аудите. Не добавляйте ключи, runtime state, экспортированные профили, account TOML и архивы в git.

## Установка одной командой

Review-сборка находится в `fix/awg-warp-safe-persistence`: [Draft PR #1](https://github.com/redoxprison-pixel/amnezia-warp-fix/pull/1). `main` пока содержит старую 6.60. Прежняя ссылка с `/main/govpn.sh` работает, но до объединения PR скачивает старый код. Main и production VPS в процессе разработки не меняются.

Для Linux с Bash 4+, Python 3.8+, curl, flock и root/sudo. Меню ориентировано на Debian/Ubuntu; для AWG требуются Docker и установленная Amnezia. Сначала просмотрите [install.sh](install.sh) и исходники из доверенной ветки. Затем:

```bash
curl -fsSL https://raw.githubusercontent.com/redoxprison-pixel/amnezia-warp-fix/refs/heads/fix/awg-warp-safe-persistence/install.sh | sudo bash
```

Если уже работаете от root, замените `sudo bash` на `bash`. Установщик проверяет Bash и четыре встроенных Python модуля, делает приватную резервную копию прежнего скрипта, блокирует одновременное обновление и атомарно устанавливает `/usr/local/bin/govpn`. После этого открывается меню. Это выполнение кода из доверенного репозитория, не криптографическая подпись поставки. Для установки без запуска меню используйте `sudo bash -s -- --no-run` справа от `|`.

Проверка версии: `/usr/local/bin/govpn version`. Старый кеш больше не выдается за новое обновление. Запуск: `sudo /usr/local/bin/govpn`. Сама установка файла не включает WARP. Полное меню выполняет подготовку системы, поэтому для простого просмотра версии используйте `version`.

Обновить уже установленную review-сборку:

```bash
sudo /usr/local/bin/govpn update
```

Обновление через меню **4 → 2**; команда CLI осталась прежней. Старый updater с источником `main` не видит Draft PR: для перехода используйте установщик выше. До отдельного выпуска в main review-ветка должна существовать; автоматического скачивания старого main при ее недоступности нет.

## Главное меню

- **1 - Клиенты**: компактный список имен/IP, метки VPS/WARP и состояние связи; в карточке выход, подпись и подробности. Создание/отзыв доступа и экспорт выполняются через Amnezia. Старое создание peer, вопрос о порте и меню ключей/QR убраны.
- **2 - WARP**: дополнительный выход с автоматическим сохранением и повторным использованием настройки. Если Gemini работает через выход VPS, оставьте его: WARP не гарантирует доступность региона Google.
- **3 - Диагностика**: общий отчет и отдельные действия исправления. Они не заменяют проверку на устройстве и не исправляют регион аккаунта Google.
- **4 - Обслуживание**: backup/restore, обновление, зависимости, перезапуск и подготовка SSH. Обновление **4 → 2**, SSH **4 → 3**.
- **5 - Маршрутизация и резерв**: **1** - файл российских IPv4-сетей для исключений в Amnezia; **2** - отдельный OpenFlux резерв. Установка других VPN-протоколов и Telegram-прокси из обычного меню убрана; действующие сервисы не удаляются.
- **6 - Восстановление AWG**: сохраненный hook/WARP, не универсальный ремонт VPN.

Enter возвращает назад (в главном меню - выход), в списках клиентов обновляет данные. Меню без жирного шрифта, группы разделены пробелами. Секунды handshake скрыты из общего списка; метки VPS/WARP различаются текстом и цветом. В других режимах видимые пункты перенумеровываются подряд.

Карточка клиента: **1 - выход, 2 - имя GoVPN, 3 - сведения о связи**. Для Gemini на данном VPS: **1 → клиент → 1 → 1 (VPS)**. Массовый выбор маршрутов: **1 → r**. Системный wgcf не является обязательной зависимостью AWG: новый мастер загружает отдельную закрепленную копию при необходимости, старый неисправный «скачать wgcf» убран.

OpenFlux требует отдельного приложения на устройстве, работает как экспериментальный резерв для одного активного клиента. SHA256 binaries закреплены, секрет/ссылка сохраняются приватно; AWG, SSH и firewall не перенастраиваются. Российские IP-сети экспортируются из RIPEstat; список импортируется в Amnezia, а не применяется сервером. Это не все домены .ru/.рф и не точная геолокация. [Настройка и границы проверки](docs/reserve-and-routing.md).

## WARP на новом сервере

Откройте **2**: мастер покажет текущий этап. Если профиля нет, первое действие предложит подключить WARP. Мастер сам создаст отдельный профиль через wgcf 2.3.1, если сохраненной настройки нет; повторное включение использует ее автоматически. Ручной импорт убран из обычного меню, технический CLI для восстановления остается. Регистрация требует принятия условий Cloudflare и явного списка клиентов. Существующие account/profile при переустановке не удаляются и не перерегистрируются. WGCF release assets закреплены SHA256; реальные регистрация и handshake могут быть отклонены Cloudflare и не выполнялись в тестах.

В AWG контейнере `wg` иногда является `amneziawg-tools`. GoVPN проверяет обычные WireGuard binaries; если их нет, установка извлекает отдельные `wg`/`wg-quick` из доверенных пакетов дистрибутива. Команды AWG не заменяются. Отдельные binaries сохраняются на хосте в `/etc/amnezia-warp/<контейнер>/native-tools` и включаются в runtime для restart/recreate. Первая установка требует работающего контейнера, kernel WireGuard и NET_ADMIN. Для recreate необходима остановленная фаза, см. runbook.

Профиль и positive selection IPv4 /32 хранятся в `/etc/amnezia-warp/<контейнер>/state.json` с правами 600. При включенном managed WARP весь IPv6 AWG блокируется. Для выбранного клиента нужен внешний IPv4 DNS в его профиле (например, `1.1.1.1`): локальный DNS запрещен защитными правилами. Профиль на телефоне скрипт не редактирует. Split tunnel и IPv6 вне VPN проверяются на устройстве.

WARP не является средством гарантированной смены страны и не обещает работу Gemini. Если через обычный выход VPS Gemini работает, оставьте клиенту маршрут VPS. Плюсы, недостатки и проверка описаны в [Gemini/WARP](docs/gemini.md).

## Разработка и проверки

Скрипт самодостаточен. Редактируйте `lib/awg_warp.py`, `lib/awg_clients.py`, `lib/diagnostics.py` и `lib/access_tools.py`, затем обновляйте встроенные копии:

```bash
python3 tools/bundle.py
python3 tools/catalog_functions.py
python3 -m unittest discover -s tests -v
python3 tools/bundle.py --check
python3 tools/catalog_functions.py --check
bash -n govpn.sh
bash -n install.sh
```

Изолированные Linux проверки: `python3 tests/docker/run_update.py` и `python3 tests/docker/run.py`. Отдельный `python3 tests/docker/run_native.py` использует сеть только для доверенных пакетов Alpine (или Ubuntu с `--debian`), затем отключает ее и проверяет приватный wg-quick. Для OpenFlux: собрать `tests/docker/access.Dockerfile`, затем запустить `python3 tests/docker/run_access.py` (публичная загрузка hash-pinned release, сам контейнер без сети). `python3 tests/online_country.py` проверяет публичную схему RIPE и экспорт во временный каталог. Production VPS не используется. Ни эти тесты, ни общий статический каталог не подтверждают все сторонние services и доступность Gemini.

Backups включают host WARP state/tools, labels и сохраненные клиентские профили. Legacy restore не является полным автоматическим disaster recovery; ограничения перечислены в аудите. Не добавляйте ключи, runtime state, экспортированные профили, account TOML и архивы в git.

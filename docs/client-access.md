# Повторный доступ к клиенту

Сервер хранит публичный ключ peer и, при наличии, общий PSK. Публичный ключ не позволяет восстановить клиентский приватный ключ. Наличие администратора SSH или серверного PrivateKey этого не меняет. См. [генерацию ключей WireGuard](https://www.wireguard.com/quickstart/).

## Если устройство или экспорт сохранились

1. Экспортируйте профиль в приложении Amnezia либо возьмите доверенный backup. Для импорта GoVPN нужен обычный текстовый `.conf`, не зашифрованная ссылка/QR формата Amnezia. Возможности экспорта зависят от версии приложения; если доступна только ссылка, используйте ее в самом приложении.
2. Передайте `.conf` на VPS по защищенному каналу и установите права 600. Не присылайте его в публичный чат и не публикуйте в репозитории.
3. Откройте **1 → клиент → 4**, укажите путь. GoVPN проверит, что приватный ключ дает текущий публичный ключ peer, IP соответствует клиенту, а серверный ключ и PSK совпадают. Это не изменение ключей и не подключение к внешнему Endpoint.
4. После сохранения станут доступны конфиг/QR в той же карточке. Копия хранится приватно и привязана к публичному ключу. При повторном использовании IP другим peer старый профиль не выдается.

Выданный профиль содержит секреты. Один профиль на нескольких устройствах одновременно - одна и та же личность peer, а не новые независимые клиенты. Для второго устройства обычно нужен отдельный peer.

## Если устройство и копии потеряны

Восстановить прежний приватный ключ невозможно. Создайте новый доступ в Amnezia, проверьте соединение и затем отзовите старый. При подозрении на компрометацию старое устройство/профиль следует отозвать без ожидания. Изменение ключа существующего peer инвалидирует старые профили; GoVPN не делает это автоматически ради кнопки «показать конфиг».

Legacy создание/удаление peers внутри монолита пока требует отдельной транзакционной переработки. В новой карточке восстановление доступа не вызывает этот код неявно. Исходные экспортированные файлы и архивы храните защищенно; host profiles включены в private backup, но автоматический импорт всего каталога из legacy tar пока не реализован.

## Проверка и пределы

Импорт проверяет принадлежность ключей/IP/PSK, отвергает серверный конфиг, hooks, неоднозначную структуру, управляющие символы и выдачу чужого профиля при переиспользованном IP. Он не гарантирует, что в копии актуальны внешний Endpoint, DNS и все параметры текущего приложения. Для дальнейшей выдачи предпочтителен свежий экспорт. Импорт без подходящей копии не создает рабочий приватный ключ из ничего.

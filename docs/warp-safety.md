# WARP persistence и границы безопасности

Изменения предназначены для review и стендовой проверки. Разработка и тесты не подключаются к VPS. Установка на рабочий сервер в этот PR не входит.

## Что исправлено

- Исключены все записи в Docker storage directories. Используются `docker inspect`, `docker cp` и `docker exec`, адресованные одному контейнеру. После inspect операции закреплены за полным ID, а не за переиспользуемым именем.
- Исходный `start.sh` и предыдущее состояние сохраняются **до** изменения. Резервная копия не зависит от уже удаленного временного файла. Имена резервных копий уникальны.
- Состояние хранится на хосте отдельно от writable layer контейнера: `/etc/amnezia-warp/<имя>/state.json`. Это JSON с нормализованным профилем, списком клиентов и интерфейсом. Файл содержит приватный ключ. Каталоги имеют права 700, файлы 600; запись атомарная с fsync. Одновременные изменения одного контейнера блокируются через flock.
- Существующие файлы непосредственно в `/etc/amnezia-warp` не перезаписываются. Первый setup может перенести существующий профиль и список из известных хостовых/контейнерных путей. Если список не найден, операция отказывает до изменения сети: сначала требуется явный выбор клиентов в пункте 3. Пустой список не подставляется автоматически. Ручной import требует явных файлов; повторный import поверх существующего состояния отклоняется.
- `start.sh` содержит только вызовы одного helper перед оригинальной инициализацией AWG и перед завершающим `tail`. Helper читает актуальный список из файла. Известные старые блоки удаляются только между согласованными markers. Неизвестный/пустой startup не заменяется придуманным шаблоном.
- Каждое применение получает неизменяемый каталог `/opt/govpn-warp/<uuid>` с helper и данными. Сначала копируется весь каталог, затем для работающего контейнера startup заменяется атомарным rename. Предыдущий startup продолжает ссылаться на предыдущие полные данные при сбое копирования. Старые каталоги остаются для восстановления; они содержат ключи и не удаляются автоматически.
- Выбор клиентов положительный: только точные IPv4 /32 получают WARP mark. Неизвестные и новые клиенты идут напрямую по IPv4. Пустой список означает явное отключение всех и сохраняется как пустой список.
- Правила используют отдельную таблицу 51888, приоритет 10900, бит mark `0x40000000/0x40000000` и цепочки `GVPN_WARP_*`. Чужие таблицы и остальные биты mark сохраняются. Удаляются только точные известные старые GoVPN hooks и старое правило `priority 100 fwmark 100 lookup 100`; таблица 100 не очищается.
- Есть два механизма fail-closed: `unreachable default metric 32767` остается в таблице при исчезновении устройства WARP; filter DROP для выбранного источника запрещает любой forwarding вне `warp`, даже если policy rule утрачен. Защита расположена перед существующими ACCEPT/ESTABLISHED. NAT применяется только к выбранным источникам на WARP.
- До перестройки правил блокируется весь AWG ingress в INPUT/FORWARD обеих IP-семей. После ошибки blanket guard не снимается. Контроллер дополнительно пытается остановить именно проверенный контейнер с нулевым grace period. Автоматического отката к прямому выходу нет.
- IPv6 AWG полностью блокируется в INPUT/FORWARD, включая невыбранных клиентов. Связать IPv6 с IPv4-пирами по этому списку нельзя. IPv6-адрес туннеля и `::/0` удаляются из импортированного профиля. IPv6 транспорт Endpoint допускается; маршрутизация клиентского IPv6 не поддерживается.
- Профиль WARP проходит проверку формата, ключей, Endpoint и адресов. DNS и автоматические маршруты отключены (`Table = off`); hooks, SaveConfig, неизвестные и повторные параметры отвергаются. Приватные ключи не попадают в аргументы команд, сообщения ошибок и логи.

## Совместимость и намеренные ограничения

Требуются Linux, root, Bash 4+, Docker CLI, Python 3.9+, `ip`, `iptables`/`ip6tables` с поддержкой `-w` и `wg-quick` **в контейнере**. Автоматической установки пакетов внутри AWG, регистрации аккаунта и загрузки неподтвержденного wgcf больше нет. Используйте уже сохраненный WARP профиль. Этот PR не меняет формат AmneziaWG и не устанавливает AWG вместо существующего контейнера.

Поддерживаются `awg0` или `wg0`, обычный `start.sh` с shebang sh/bash и последней командой `tail -f /dev/null` либо `exec tail -f /dev/null`. Скрипт с ранним exec/exit, фоновым процессом или WARP-командами вне известных markers требует отдельной ручной адаптации. Такой отказ происходит до изменения контейнера. Bind mounts на управляемых путях и host/shared network namespace отклоняются. Таблица/приоритет/mark/цепочки выше зарезервированы за этим helper; неизвестное содержимое таблицы или конфликт приоритета вызывает отказ.

Выбранным WARP-клиентам запрещены обращения к самому контейнеру и маршруты к другим интерфейсам, включая VPN DNS на адресе AWG, LAN и других клиентов. Им нужен внешний IPv4 DNS, доступный через WARP. Иначе возникает утечка через локальный DNS resolver. Клиентский трафик, который вообще не направлен в VPN клиентским `AllowedIPs` (например, IPv6 вне туннеля), сервер блокировать не может. Для полного туннеля нужно отдельно проверить конфигурацию клиента и направить обе IP-семьи в VPN либо отключить IPv6 на клиенте.

Смена выбора не очищает чужую conntrack table. Уже открытые соединения могут сохранить старый NAT tuple до истечения timeout; приложениям может понадобиться переподключение. Filter guard и policy marking применяются и к существующим потокам, поэтому выбранный источник все равно не может выйти через обычный uplink.

Восстановление интерфейса и правил не подтверждает handshake или успешный выход в Cloudflare. При потере связи с Endpoint пакеты остаются направленными в WARP и не уходят на прямой uplink. `status` показывает сохраненную политику и состояние Docker, а не подтвержденный WARP egress.

Обновление доступно через обычное меню **8 → Система и управление → 2 → Обновить скрипт** и `govpn update`. Пока PR остается черновиком, `UPDATE_REF` указывает на `fix/awg-warp-safe-persistence`; команда не скачивает старый код из `main`. При подготовке стабильного выпуска ref нужно явно переключить на `main` после включения исправлений. Удалять ветку до смены ref в установленной копии нельзя. Если ветка недоступна, обновление завершается ошибкой и сохраняет установленную версию, без автоматического перехода на другой источник.

Загрузка выполняется в приватный временный каталог по HTTPS. Перед установкой проверяются Bash-синтаксис, версия и синтаксис встроенного Python WARP backend. Загруженный код для проверки не исполняется. Затем создается резервная копия установленного скрипта в `${BACKUP_DIR}/govpn-update.*/govpn.sh` с правами 600 и выполняется атомарная замена. Ошибка загрузки, валидации, backup или установки не считается успехом. Одновременные обновления блокируются через `flock` из util-linux. Это проверка формата из доверенного репозитория, а не криптографическая подпись содержимого.

`govpn update --yes` работает без диалогов и после установки завершает команду, не открывая меню. `--force` разрешает переустановку той же версии или явный переход на более старую версию, но не обходит валидацию WARP backend. Интерактивный пункт после установки предлагает Enter для запуска новой версии. Кеш версии привязан к ветке; старый кеш от `main` игнорируется.

Старая копия GoVPN на VPS по-прежнему загружает код из `main`: один Draft PR не меняет источник в уже установленном файле. Чтобы обычное меню получило исправления, нужен отдельный выпуск в `main` или разовая установка проверенной review-версии. В рамках PR это на production не выполнялось. Сам скрипт остается самодостаточным: Python helper встроен, дополнительные файлы из репозитория для запуска не нужны.

## Удаление и переустановка через меню (6.63)

В меню **1 → 3** команда setup использует существующий state.json либо ищет профиль в `/etc/amnezia-warp/<имя>/warp.conf`, `/etc/amnezia-warp/warp.conf`, `/etc/amnezia-warp/wgcf-profile.conf`, затем в известном runtime release и legacy контейнерных путях `/opt/warp/warp.conf`, `/etc/amnezia/amneziawg/warp.conf`, `/etc/wireguard/warp.conf`. Список берется из state.json, хостовых clients.list/warp-clients.list или legacy `/opt/warp/clients.list` и `/opt/amnezia/awg/warp_clients.txt`. При нескольких источниках используется первый по этому порядку; исходные файлы не перезаписываются. Это перенос существующих данных, без новой регистрации WARP. Если контейнер остановлен, явный setup только устанавливает hook и данные; сам контейнер не запускается.

В меню **1 → 4** удаляется активный WARP: startup blocks, известные routing/firewall resources и интерфейс warp. Удаление работает без state.json, без работающего туннеля и без запуска wg-quick. После явного подтверждения восстанавливается возможность прямого выхода IPv4/IPv6 в рамках исходной конфигурации AWG; собственные IPv6 DROP тоже снимаются. Глобальные firewall tables и чужие rules не очищаются. AWG-интерфейс, контейнер, общие WireGuard packages, исходные профили и backups сохраняются. Поэтому последующая переустановка может использовать прежний профиль. Ошибка удаления под guard приводит к попытке остановки контейнера и требует проверки статуса.

Состояние после удаления помечается `enabled=false`. Обычный restart не возвращает удаленный WARP; restore/prepare-stopped не включают его неявно. Для явного повторного включения нужен setup, выбор клиентов через apply либо замена профиля. Пункт **1 → 2** запрашивает путь к профилю и действительно применяет его. Все профили проходят прежнюю data-only validation. Переустановка с тем же аккаунтом не гарантирует новый IP или иной регион у Google.

```bash
sudo govpn warp-safe amnezia-awg2 setup
sudo govpn warp-safe amnezia-awg2 remove
```

`remove` означает явное разрешение прямого выхода и не является способом проверки fail-closed. Для диагностики региона Gemini нужен trace с самого VPN-клиента и фактический результат Gemini; WARP IP в серверном меню этого не доказывает.

## Миграция на стенде

Ниже пример для будущего ручного запуска после проверки PR. Это не отчет о выполненных действиях на VPS. Имена исходных файлов нужно сверить с уже существующим бэкапом; они не предполагаются автоматически.

```bash
# Использовать локально сохраненный govpn.sh из проверенного commit этой ветки.
# Файл со списком должен содержать по одному выбранному IPv4 /32 в строке.
# Явно пустой файл означает, что ни один клиент не выбран.
sudo bash govpn.sh warp-safe amnezia-awg2 import \
  --config /etc/amnezia-warp/warp.conf \
  --clients /etc/amnezia-warp/clients.list \
  --iface awg0

# Import сохраняет состояние и исходный start.sh, не применяя сеть.
sudo bash govpn.sh warp-safe amnezia-awg2 restore
sudo bash govpn.sh warp-safe amnezia-awg2 status
sudo bash govpn.sh warp-safe amnezia-awg2 selected

# Явный выбор. Изменение временно блокирует весь AWG трафик.
sudo bash govpn.sh warp-safe amnezia-awg2 apply 10.8.1.2/32 10.8.1.3/32
# Явно снять выбор всех клиентов; IPv6 остается заблокированным.
sudo bash govpn.sh warp-safe amnezia-awg2 apply

# Сохранение Endpoint и замена профиля проходят тот же backup/apply путь.
sudo bash govpn.sh warp-safe amnezia-awg2 endpoint engage.cloudflareclient.com:2408
sudo bash govpn.sh warp-safe amnezia-awg2 replace-profile --config /secure/reviewed-profile.conf
```

Исходный account TOML не нужен для поднятия существующего туннеля. Его сохраненная копия остается на хосте для будущих ручных операций с аккаунтом. Перерегистрация при каждом запуске запрещена. Общий `govpn backup` включает `/etc/amnezia-warp` и создает приватный архив; это архив с секретами, его нельзя публиковать или добавлять в git.

## Restart, recreate и отказ

Обычный restart и reboot Docker host сохраняют writable layer и установленный hook. На каждом старте blanket guard устанавливается **до** оригинального startup AWG; apply освобождает трафик только после установки маршрута, NAT и filter guard. Helper обрывает startup при неудаче.

Пересоздание или обновление образа может удалить hook и пакеты из writable layer. Одного хостового JSON недостаточно для автоматического восстановления до первого пакета. Внешний watcher не обеспечивает эту гарантию и в PR не используется. Перед recreate нужно остановить контейнер и исключить его автоматический/управляемый Amnezia запуск до установки hook. Созданный заново контейнер должен оставаться остановленным:

```bash
sudo bash govpn.sh warp-safe amnezia-awg2 prepare-stopped
# Только после успешного результата оператор отдельно запускает контейнер.
```

`prepare-stopped` работает через Docker cp, не запускает контейнер и не меняет Docker restart policy. Он откажет для работающего контейнера. Самопроизвольный recreate/start через приложение Amnezia обходит установленную защиту и не поддерживается; для такого жизненного цикла нужен управляемый образ/entrypoint. Несовместимый новый `start.sh` требует ручного review. Для уже испорченного startup восстановите проверенный оригинал из резервной копии через Docker cp в остановленный контейнер, затем снова установите hook; неизвестный startup автоматически не чинится.

После ошибки частичного применения новое желаемое состояние может уже быть сохранено, а контейнер остановлен. Предыдущее состояние и точный startup находятся в `/etc/amnezia-warp/<имя>/backups/*.json`. Сначала исправьте причину и повторите `prepare-stopped`/ручной старт либо `restore` для работающего контейнера. Для возврата к предыдущей политике используйте проверенный профиль и список из backup через явные команды. Не удаляйте guards и не очищайте policy routing как способ восстановления. При недоступном Docker daemon остановку подтвердить нельзя; требуется ручная проверка на хосте.

Удаленный и затем переиспользованный IPv4 сохраняет прежний выбор WARP до явного изменения списка. Идентичность клиента в текущем формате определяется адресом, не public key. Новому владельцу того же адреса нельзя обещать прежнюю пользовательскую политику без проверки списка.

## Проверки

```bash
python3 -m unittest discover -s tests -v
python3 tools/bundle.py --check
bash -n govpn.sh

# Только локальный Docker. Не использовать production context/DOCKER_HOST.
docker build -f tests/docker/Dockerfile -t govpn-warp-test:local .
python3 tests/docker/run.py
# Отдельные updater-тесты с настоящим Linux flock, без загрузок из сети.
python3 tests/docker/run_update.py
```

Unit tests проверяют валидацию, идемпотентный startup patch, приватные права, backup до записи, пустой список, изоляцию контейнера, отказ и отсутствие ключей в ошибках. Docker tests создают временный контейнер с `--network none` и `NET_ADMIN`; никаких host mounts или Docker socket mounts нет. Внутри него используются настоящие kernel routes, iptables и raw packets через veth. `wg-quick` заменен локальной fixture с dummy interface для воспроизводимых отказов. Тесты не подтверждают совместимость конкретного production образа AmneziaWG, handshake Cloudflare или доступность внешнего сервиса.

Основания реализации: [Docker запрещает прямое изменение storage directories](https://docs.docker.com/engine/storage/drivers/overlayfs-driver/), [wg-quick Table=off и исполняемые hooks](https://git.zx2c4.com/wireguard-tools/about/src/man/wg-quick.8), [policy routing](https://www.man7.org/linux/man-pages/man8/ip-rule.8.html).

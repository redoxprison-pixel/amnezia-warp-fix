# Аудит govpn.sh

База review: main `be7f7da1cc495d9f96e950c672e14b90447c991b`, версия 6.60. Исправления подготовлены в `fix/awg-warp-safe-persistence`, версия 6.70. Production VPS и его конфигурация не использовались как тестовое окружение.

## Исправленные дефекты AWG/WARP

1. **Критический: прямые записи во все Docker overlay2 слои.** `_awg_patch_start_sh` и `_awg_emergency_restore` могли изменить другие контейнеры и общие image layers. Полностью заменены адресными операциями Docker API через CLI. Аварийная функция больше не генерирует непроверенный startup со статической подсетью.
2. **Высокий: потеря сохраненного состояния.** Профиль, account и список хранились только внутри контейнера; повторная настройка регистрировала новый account. Профиль и список теперь импортируются на хост один раз и переживают потерю контейнера. Обычный restart восстанавливается startup hook; recreate имеет обязательную остановленную фазу, описанную в runbook.
3. **Высокий: broken backup startup.** Код удалял `tmp_file`, затем копировал его в backup. Новый backup сохраняет фактически прочитанный оригинал до изменения, отдельно для каждого контейнера и каждой операции.
4. **Высокий: fail-open при потере WARP.** Старый код очищал routes до проверки tunnel, подавлял ошибки и не имел filter kill switch. Теперь ingress закрывается до изменений, таблица содержит unreachable fallback, а выбранные источники не могут выйти через другие интерфейсы. Неудачное применение не считается успехом.
5. **Высокий: отрицательный список исключений.** Catch-all MARK направлял через WARP любого нового клиента, которого еще не было в списке исключений. Теперь positive selection точных /32 с явным RETURN и очисткой только выделенного mark bit для остальных.
6. **Высокий: IPv6 обход.** Удаление IPv6 из WARP профиля не запрещало AWG IPv6. Теперь явно блокируются INPUT и FORWARD IPv6 всего AWG интерфейса. Ограничения клиентского split tunnel вынесены в runbook.
7. **Высокий: изменение чужой policy routing.** Удалялись любые rules lookup 100, очищалась вся таблица и NAT по подстроке warp. Новый backend не очищает чужие таблицы и удаляет только точные известные legacy hooks. Конфликты зарезервированных ресурсов приводят к остановке применения.
8. **Высокий: shell interpolation и исполняемый профиль.** IP и данные профиля попадали в shell-команды, wg-quick поддерживает исполняемые hooks. Контроллер использует argv, строгие IPv4 /32 и ограниченный нормализованный профиль без hooks/SaveConfig. Ошибки subprocess не печатаются вместе с ключами.
9. **Средний: несогласованный UI rollback.** Меню сохраняло старый список из неверного пути, проверяло source rules при фактическом fwmark routing и откатывало только часть состояния. Все AWG WARP entry points теперь используют единую операцию backup/save/apply. Empty selection проходит тот же путь.
10. **Средний: отсутствие идемпотентности и проверки ошибок.** Повторные старты добавляли MSS/NAT/rules, startup patch маскировал ошибки через true. Новый runtime восстанавливает только свои цепочки под blanket guard, не размножает hooks и проверяет lookup выбранных клиентов.
11. **Средний: секреты в архивах с широкими правами.** `do_backup` теперь работает с umask 077, включает хостовое состояние и проверяет результат tar. `.gitignore` исключает известные runtime profiles/keys/backups; fixture keys синтетические.
12. **Средний: возврат небезопасной версии через updater.** Обновление через исходное меню восстановлено в 6.62 с источником из review-ветки, приватными временными файлами, syntax/backend validation, backup до установки, flock и атомарной заменой. Старый backend не принимается даже с --force; непроверенного fallback download нет.

## Область просмотра и оставшийся технический долг

Статический поиск опасных конструкций выполнен по всему монолиту: входные команды, установка/обновление, AWG lifecycle и peer operations, backup/restore, host routing, 3X-UI, Hysteria, MTProto и nginx/SSL helpers. Подробный ручной разбор и динамические тесты сосредоточены на AWG/WARP и вызывающих его путях. Полноценная проверка всех внешних сервисов требует отдельных стендов и не может быть заменена shell syntax check. Этот PR не является подтверждением безопасности всего root manager.

За пределами исправленного AWG/WARP пути остались самостоятельные риски:

- `init_config` и `save_config` используют shell source для локального `/etc/govpn/config`. Его содержимое должно считаться исполняемым root-кодом; миграция всех старых параметров на data-only формат требует отдельного изменения.
- Peer editing, scanners, 3X-UI helpers и legacy changelog helper используют предсказуемые `/tmp` имена. На многопользовательском хосте возможны symlink collisions и раскрытие временных конфигов. Новый WARP backend использует только приватные mkdtemp/mkstemp; старые функции не следует считать защищенными этим PR.
- В 3X-UI и вспомогательных генераторах остаются Python/SQL/shell строки с пользовательскими значениями. Нужен отдельный переход на параметризованные API и argv.
- Установщики host компонентов и сторонних proxy/scanner binaries доверяют удаленным releases/scripts без единой политики pin/checksum. Автозагрузка wgcf из AWG WARP пути убрана, остальные установки требуют отдельного review.
- Восстановление полного архива в legacy `_backup_restore` доверяет содержимому архива. Безопасное извлечение недоверенных tar и единая транзакция восстановления всех компонентов не реализованы. Восстановление WARP профиля внутри этого меню направлено через валидирующий backend; хостовый state bundle не импортируется автоматически из архива.
- `govpn` выполняется с root и управляет сетью. Ошибки прав/daemon/kernel нельзя превратить в абсолютную гарантию. Если Docker недоступен, контроллер не может подтвердить остановку контейнера. Для recreate со сторонним auto-start нужна интеграция с образом/entrypoint, а не фоновый watcher.

Для этих оставшихся пунктов нужны отдельные изменения; они явно перечислены, чтобы Draft PR не создавал ложного впечатления полной hardening всего монолита. Запуск на production в рамках этого аудита не выполнялся.

## Первая установка и пределы Gemini в 6.65

Миграция существующего WARP ошибочно подавалась в меню как полноценная установка с нуля. Добавлен 21 regression case: первый запуск, отказ/отмена, существующий/поврежденный профиль, сохранение account, retry generate, неопределенный register, SHA256/cache, зависимости/kernel preflight, первый импорт, native awg и частичный отказ combo. ## UX, повторная выдача профилей и конфликт wg в 6.66

Подтвержден реальный случай: `/usr/bin/wg` и `awg` внутри amnezia-awg2 оба являются amneziawg-tools. Проверка 6.65 ошибочно ожидала обычный WireGuard по тому же имени. Новый preflight выбирает совместимую пару либо извлекает обычные wg/wg-quick из доверенных пакетов дистрибутива в приватный payload, не устанавливая их поверх AWG. Alpine .apk проверяются через apk verify; Debian download использует аутентифицированные package indexes. Account и маршруты не применяются до успешной проверки. Host payload входит в backup и копируется в immutable runtime при восстановлении. Не выполняется fallback на AWG wg при отказе native WG.

Объединены список клиентов, карточка и выбор выхода; MTProto/проброс портов перенесены в дополнительные задачи. Импорт экспортированного .conf и последующий экспорт проверяют текущий клиентский public key, Interface IP, серверный key и PSK. Приватные ключи передаются в pubkey через stdin, не argv. Серверные конфиги, hooks и profile для другого владельца IP не принимаются. Сохраненные profiles имеют режим 600 и не меняют peers. Отсутствие профиля ведет к инструкции по восстановлению, а не к неявной ротации ключей. Полноценный refresh Endpoint/obfuscation/app compatibility этим не подтверждается.

Добавлен install.sh с syntax/embedded AST checks, private backup, общим с updater flock и атомарной установкой. Старая ссылка на main по-прежнему указывает на main; review installer явно использует ветку, без скрытого изменения main. Подготовка SSH в 8 → a выводит валидированный клиентский ProxyJump config и инструкции; sshd/firewall/authorized_keys не меняются, проверка реального внешнего доступа не имитируется.

Итог 6.66: 96 unit cases PASS в Linux без сети; macOS 92 PASS и 4 skip (реальный flock и root installer). Предыдущая kernel matrix PASS. Отдельные локальные Alpine и Ubuntu tests получили доверенные packages, воспроизвел AWG под всеми стандартными именами wg, сохранил исходные binaries по SHA256 и после отключения сети поднял/удалил реальный WireGuard link приватным wg-quick. Использовались синтетические ключи и documentation-only Endpoint, без account Cloudflare/production VPS. Это не тест Gemini и не проверка всей legacy manager поверхности.

## Меню, задержки и кеш в 6.67

Исправлены реклама старой версии из кеша, несогласованная/пропущенная нумерация и чтения перед первым экраном клиентов. Основные меню используют единый массив «номер - действие». Главное меню Amnezia: 1 клиенты, 2 WARP, 3 диагностика, 4 обслуживание, 5 дополнительные функции, 6 recovery. Update остается вторым действием обслуживания, путь теперь 4 → 2. Скрытые конфликтующие цифровые shortcuts удалены.

Клиентский список собирается одним Docker exec с общим timeout 6 секунд; PrivateKey/PSK отфильтровываются внутри контейнера. Получение контейнеров ограничено отдельно. Перед чтением видна загрузка. Просмотр policy использует host-only state, отсутствующий state дает unknown. Сбой не применяется как пустая политика. Криптографическая проверка профиля перенесена с открытия карточки на выдачу; наличие файла не объявляется его проверкой.

WARP показывает этап до выбора действия: нет профиля, pending, saved, legacy, repair, ready или stopped. Первое действие зависит от этапа; тест отсутствующего WARP не предлагается. Первый импорт и создание объединены в подключение, смена профиля доступна отдельно при существующей настройке. Pending использует resume-only с запретом новой регистрации. Остановленный контейнер не запускается автоматически.

Числовое сравнение версий используется и на границе кеша, и в баннере; более старая удаленная версия не возвращает старое уведомление. Добавлены 15 regression tests относительно 6.66: навигация, последовательность во всех режимах/этапах, открытие 31 клиента и возврат с двумя Docker запросами, реальный timeout subprocess, старые/equal/new версии и resume-only. Всего 111 unit tests; macOS 107 PASS и 4 skip, Linux полный набор. Локальный Docker также проверяет secret-filtered snapshot, этапы WARP и прежнюю kernel matrix. Это не отчет об устранении неисправности Docker на конкретном VPS и не подтверждение работы Gemini. Подробности и первичные UX-примеры: [menu-flow](menu-flow.md).


## Интерфейс и отчет 6.68

Ввод основных меню переведен на прямое чтение терминала; Enter возвращает назад, списки клиентов обновляются. Убраны остаточные неограниченные Docker чтения шапки и группового выбора, внешний запрос WARP IP из шапки. Причина зависания на пользовательском VPS не подтверждена - production не исследовался. Добавлены настоящие PTY проверки.

Ручной импорт WARP скрыт из обычного мастера; CLI восстановления сохранен. Существующие account/profile повторно используются, не удаляются при отключении. Backend пишет только фиксированные этапы в stderr по опции GOVPN_PROGRESS=1; итог различает ошибку, подготовленный остановленный контейнер и наличие туннеля/правила. Наличие интерфейса не называется доступом к Gemini.

Общий отчет встроен в единый govpn.sh. Он не выполняет сторонние installers/diagnostics и не меняет сеть. Чтение Docker и HTTPS ограничено, поля внешнего ответа проходят allowlist. JSON state не печатается. Правила выбранных клиентов проверяются по отдельным строго проверенным IPv4 /32 аргументам. Наличие цепочек и точных правил - снимок, не доказательство полного клиентского packet path или региональной доступности сервисов. Прежние риски legacy модулей из аудита остаются.

Проверки 6.68: 131 тест прошел в одноразовом Linux-контейнере без сети; macOS - 126 прошли, 5 пропущены (Linux flock и root installer). Локальный kernel packet-path набор, включая отчет о выбранных клиентах и отсутствующем IPv6 INPUT правиле, прошел. Реальная регистрация Cloudflare, пользовательский VPS и клиент Gemini не использовались.


## 6.69: сокращение поверхности обычного меню

Отключены legacy создание/удаление AWG peer и общий установщик протоколов; их прямые helpers также отказывают без Docker/SQL/генерации ключей. Из обычного AWG UI удалены QR/конфиг/импорт ключа и создание MTProto/Telemt, Scanner и веб-установка. Старые файлы/сервисы не уничтожаются. Legacy код остальных модулей остается в исходнике и не объявляется полностью проверенным.

Старый eval-экран зависимостей заменен ограниченной проверкой фактических базовых команд. wgcf нужен только для новой регистрации, поэтому отсутствие в PATH не Fail. Исправление пакетов имеет явное подтверждение, фиксированный список argv, блокировку и повторную проверку. Восстановление WARP предлагается отдельно только для включенного managed state; нет автоматического fail-open или смены страны Gemini.

Отдельный access_tools backend добавляет экспериментальный OpenFlux L4 и экспорт страны для клиентской Amnezia. Hash-pinned release v0.17.1, DynamicUser/LoadCredential, пустые capabilities, отсутствие публичного direct listener; чужой unit не заменяется. Ключ/ссылка сохраняются одним приватным атомарным state и повторно материализуются без смены ключа. Процесс active не называется рабочим каналом. Backup содержит конфигурацию/ключ; cookies systemd StateDirectory отдельно не архивируются.

RIPE экспорт строго ограничен IPv4 CIDR и размером ответа, исключает адрес VPS, не меняет iptables/маршруты и использует официальный формат импорта Amnezia. Списки страны не гарантируют доменный обход, точную геолокацию или корректность уже существующих исключений. Полная проверка возможна только после импорта на устройстве. Источники и подробности - docs/reserve-and-routing.md.

Проверки 6.69: 158 тестов PASS в одноразовом локальном Linux-контейнере без сети; macOS - 152 PASS, 6 skip для root installer/flock. Настоящий закрепленный OpenFlux core прошел make-link/parse-link и непривилегированный L4 запуск без сети, unit прошел systemd-analyze verify. Публичный ответ RIPE и экспорт проверены отдельно. Kernel matrix AWG/WARP проходила в 6.68; ее контроллер и runtime в этой итерации не менялись. Реальные captcha, клиентский импорт, операторские белые списки, Gemini и production VPS не тестировались.


## 6.70: обычные экраны без эвристики активности и технических команд

Из списка/карточки убраны давность связи и число «активных» клиентов в шапке: это оценка по 180-секундному handshake, а не online status. Выбор выхода вынесен на отдельный экран с review/подтверждением/этапами/итогом. stdout backend не смешивается с меню. После успешного apply повторно читается host policy; несовпадение и ошибка не считаются успехом. Повторный выбор текущего выхода - noop.

Исправлено повторное включение исторических WARP-клиентов при выборе выхода для одного клиента из отключенного состояния. В этом случае применяется только выбранный /32; если WARP уже включен, остальные выбранные адреса сохраняются. Backend guard/fail-closed/IPv6 policy не менялись.

Пункт «Восстановление AWG» снят с главного экрана и списка, поскольку он выполняет только операции WARP. Раздел 4 → 7 предлагает подготовку сохраненного WARP в остановленном контейнере либо повторное применение в работающем, по состоянию и с подтверждением. Новые ключи/регистрации не создаются, контейнер в остановленной фазе не запускается. Преимущества WARP и границы пояснены отдельно в docs/warp-purpose.md.

Проверки 6.70: 172 теста PASS в локальном Linux-контейнере без сети; macOS - 166 PASS, 6 skip. Новые проверки покрывают настоящий PTY диалог карточка/выбор/подтверждение/итог, отмену, noop, ошибку применения и сверки, сохранность остальных включенных клиентов и выбор одного клиента из выключенного WARP. Восстановление проверено для остановленного, работающего, отключенного и отсутствующего состояния. Backend WARP, OpenFlux и сетевые правила не перерабатывались; production VPS и Gemini не использовались.

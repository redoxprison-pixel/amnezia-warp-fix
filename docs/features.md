# Какие функции GoVPN нужны

Проверка исходников версии 6.65 от 31 октября 2026 года. Рассмотрены все разделы меню, связанные helpers и скрытые модули. Это оценка кода и необходимости для сценария «AmneziaWG на VPS, Gemini на клиентском устройстве». Она не означает, что установлены и проверены все поддерживаемые сервисы. Production VPS не использовался.

## Для Amnezia и Gemini

- **Клиенты AWG, пункт 4**: полезен список имен, IP и последнего handshake. Чтение имен исправлено: `clientId` связывается с публичным ключом peer, поддерживается старый формат clientsTable. Имена не выводятся из случайного совпадения IP у другого ключа. Ручные подписи GoVPN сохраняются отдельно. Открытие списка больше не устанавливает qrencode.
- **Конфиг и QR**: нужны для выдачи профилей, которые создавал GoVPN. Для существующих клиентов Amnezia сервер обычно не предоставляет клиентский приватный ключ. Старый поиск по подстроке IP мог выдать серверный awg0.conf; он удален. Теперь читается только точный профиль в `/etc/govpn/awg_clients`, с проверкой Interface Address и клиентского default route. Отсутствие профиля не повод удалять работающего клиента - используйте экспорт приложения.
- **Создание и удаление peers**: нужны, если GoVPN используется как самостоятельный AWG manager; дублируют Amnezia. В legacy коде остаются жесткая подсеть 10.8.1.x, поиск занятого IP по подстроке, неатомарные изменения runtime/config/clientsTable, предсказуемые временные файлы, интерполяция имени в Python и сообщения об успехе без полной проверки. Backup не всегда останавливает операцию при отказе. Эти операции требуют отдельной переработки; для обычного использования предпочтительно создавать и отзывать клиентов в Amnezia. Исправление чтения имен не является исправлением этого lifecycle.
- **WARP мастер, пункт 1**: дополнительный выход для тех клиентов, которым он нужен. Переустановка использует сохраненный профиль; первая установка в 6.65 отдельно создает аккаунт через закрепленный wgcf после принятия условий либо импортирует готовый файл, с явным выбором клиентов. «Регион» AWG заменяет профиль, не обещает страну выхода. Если после удаления WARP Gemini работает, WARP для этого сценария не требуется.
- **Выбор клиентов WARP, пункт 3 / w**: полезен только при включенном WARP. Выбор теперь по порядковому номеру, поэтому одинаковые последние октеты в разных подсетях не путают клиентов. В combo устранен конфликт двух пунктов 3. Ошибка чтения peers закрывает меню до применения, а не превращается в пустой список. Маршрутизация по-прежнему использует точные IPv4 /32, IPv6 AWG блокируется при включенном managed WARP.
- **Статус и тест WARP, пункт 2**: проверяет серверную сторону и выбранный выход, помогает искать сбои. Успешный curl или IP 104.x не подтверждает, что Gemini разрешил регион, аккаунт и конкретную сессию браузера. Финальная проверка выполняется на устройстве через Amnezia.
- **Аварийное восстановление, !**: полезно для восстановления сохраненного hook/WARP выбранного контейнера. Это не универсальный ремонт всех конфигураций AWG. Recreate требует отдельной остановленной фазы, см. runbook. Не использовать как обычную кнопку перезапуска.

## Система и управление, пункт 8

- **Резервные копии**: нужны. Архивы содержат ключи, не публикуйте их. Backup включает WARP state и локальные подписи клиентов. Однако legacy backup не сохраняет все компоненты транзакционно, может пропустить отдельный неудачный copy, а восстановление не применяет все сохраненные данные автоматически. AWG config, host state, local labels и выдаваемые клиентские профили требуют проверки состава и отдельного плана восстановления. Это еще не подтвержденный полный disaster recovery.
- **Восстановление архива / rollback**: аварийный инструмент. Legacy restore доверяет tar, копирует выбранные компоненты и может вернуть старый govpn без валидации updater. Не запускать с недоверенным архивом. Новое сохранение labels пока предполагает ручное восстановление их каталога с правами 700/600; автоматического импорта нет.
- **Обновление, 8 → 2**: нужно. Проверены скачивание, ошибки, backup, атомарная установка и блокировка. Источник привязан к review-ветке; после релиза переключение на main должно быть отдельным изменением. Проверка синтаксиса не заменяет доверие к исходному репозиторию.
- **Зависимости и конфликты**: полезны для диагностики. Вариант с исправлением устанавливает пакеты и меняет хост; это не просто просмотр. В диагностике используется eval статических команд, поэтому вывод нельзя считать независимым аудитом безопасности.
- **Restart AWG / host WARP / x-ui**: полезен по необходимости; прерывает соединения соответствующего сервиса. Host WARP и WARP внутри AWG - разные сущности. Не надо перезапускать оба ради Gemini.
- **Домен / SSL / сайты / self-steal**: нужны для Xray/nginx сценариев, не для обычного AWG. Изменяют веб-сервер, сертификаты, конфигурацию и порты. Требуют отдельного стенда с доменом.
- **Установка компонентов**: нужна при развертывании нового сервера. На работающем AWG не требуется ради имен клиентов или Gemini. Есть загрузка и выполнение внешних установщиков без общей политики pin/checksum. Совместимость с актуальными remote releases в этом PR не подтверждена.
- **Перезагрузка VPS**: только обслуживание; обычная смена подписи клиента ее не требует.
- **Полное удаление GoVPN**: удаляет manager, его каталог с backups/labels и часть правил, но не все установленные им сервисы и не host WARP state. Название нельзя трактовать как полный uninstall VPN. Перед ним сохраните нужные данные отдельно.

## Остальные видимые разделы

- **3X-UI: клиенты, inbound templates, ссылки/QR, лимиты и включение**: полезны только при установленном 3X-UI. Код использует API и прямую запись SQLite; эти способы могут расходиться с runtime панели. Есть интерполяция данных и временные helpers в /tmp. Нужен отдельный стенд с конкретной версией панели. На одном AWG их можно не использовать.
- **3X-UI: host WARP, RU outbound, geo routing и geofiles**: отдельные маршруты Xray, не выбор AWG клиентов. Порог размера geosite не подтверждает наличие нужных тегов. Ежедневный cron скачивает файлы прямо в рабочие пути и перезапускает x-ui без единой валидации/rollback. Для AWG не нужен.
- **Reality SNI scanner, шаблоны Reality/xHTTP/gRPC, переименование inbound и флаги**: удобства для Xray. Не исправляют AWG/Gemini. Scanner может скачивать бинарник, Go toolchain и собирать latest. «Анализ безопасности» использует эвристики и eval вывода helper; это не гарантия безопасности протокола.
- **MTProto, пункт 5**: отдельный Telegram proxy, движки mtg и telemt, домены FakeTLS, пользователи и ссылки. Не нужен для Gemini через Amnezia. Установка меняет firewall/порты и использует внешние Docker images/бинарники. Тестов Telegram и этих движков здесь нет.
- **iptables проброс, пункт 6**: нужен для входного узла/каскада между серверами. Для одного AWG VPS обычно лишний. Меняет host DNAT/REDIRECT/MASQUERADE и иногда hosts, а не WARP внутри контейнера. Валидация IPv4 местами проверяет только форму, диагностика может объявлять успех после подавленных ошибок. Полная проверка нужна на отдельной паре серверов.
- **Серверы и алиасы, 7 → 4**: адресная книга для каскадов и endpoint. Не хранит имена VPN клиентов. Для одного сервера необязательна.
- **Скорость, 7 → 1**: измеряет скачивание на VPS; loopback на 127.0.0.1 не измеряет задержку устройства до VPN. Для клиента используйте тест на самом устройстве. Текущие подписи и подстановка 0.1 мс при неудаче могут вводить в заблуждение; helper требует переработки.
- **Цепочка, 7 → 2**: отдельные запросы с VPS и пинги адресов, не end-to-end проверка всей VPN цепочки. Время неудачного запроса может показываться как успех. Полезна как вспомогательная диагностика после исправления обработки ошибок.
- **Проверка сайта, 7 → 3**: DNS/GeoIP/HTTP с VPS, для Xray возможен host SOCKS. Устранена вставка введенного домена в исполняемый Python. Результат все еще не равен проверке через AWG клиент; GeoIP берется у внешнего сервиса по HTTP.
- **Проверка сервисов, 7 → 6**: внешний ipregion, выполняемый с правами manager. Загружается из main в предсказуемый /tmp и не закреплен hash; проверяет host или host SOCKS 127.0.0.1:40000, а не ingress выбранного AWG клиента. Для проверки Gemini предпочтительнее само приложение/сайт на устройстве. Нужны закрепленный источник и отдельный ограниченный запуск.

## Скрытый и дублирующий код

Hysteria2 users/installer/UI и отдельный HY2 WARP routing остаются в файле, хотя вход h скрыт. HY2 использует старый account/profile lifecycle; безопасный AWG backend на него не распространяется. Нет основания утверждать, что протокол повсеместно заблокирован: существующий комментарий об этом не проверяет конкретную сеть. Для AWG модуль не нужен. Логичный следующий шаг - вынести его и другие опциональные proxy engines из ядра, сохранив отдельный путь установки для тех, кто ими пользуется.

Простой поиск имен вне двух сгенерированных Python блоков нашел 30 helpers, имя которых встречается только в определении. Среди них `_awg_install_wgcf`, `_awg_save_clients`, `_awg_change_region`, `_awg_tunnel_up`, `_awg_patch_start_sh`, `_awg_warp_status`, `_3xui_warp_status`, `_3xui_warp_change_region`, `_update_changelog`, `_awg_show_roscomvpn_qr`, старые stub templates и telemt user helper. Это кандидаты на удаление/вынос, а не доказательство недостижимости: shell допускает косвенные вызовы. В этой версии они не удалялись без отдельной проверки совместимости.

## Что оставить для данного VPS

Постоянно нужны Amnezia, просмотр клиентов, обновление и проверенные резервные копии. WARP - только для конкретной необходимости; работоспособность Gemini после его удаления не требует переустановки. 3X-UI, MTProto, Hysteria, каскад, сайты и scanners не обязательны. Сейчас они сохранены, чтобы не потерять уже используемые функции других установок.

Следующие самостоятельные изменения по приоритету: транзакционный AWG peer lifecycle; полноценный backup/restore; отказ от /tmp helpers и eval/интерполяции; закрепление внешних загрузок; разделение ядра и опциональных engines. До них нельзя называть весь manager полностью проверенным и безопасным.

## Проверки и источники

Динамически проверяются безопасный AWG/WARP backend, updater, парсер имен, локальные подписи, выбор клиентов, отказ при недоступном списке, ограничение экспорта конфигов и передача домена как данных. Остальные разделы оценены статически; внешние installers, настоящие 3X-UI/MTProto/Hysteria, сертификаты и регион Gemini не запускались.

Формат `clientId` / `userData.clientName`, старый map и обновление allowedIps сверены с [официальным UsersController Amnezia](https://github.com/amnezia-vpn/amnezia-client/blob/7f9b7db482b8b1662b7466937e578008cbcb716e/client/core/controllers/selfhosted/usersController.cpp) и [моделью списка клиентов](https://github.com/amnezia-vpn/amnezia-client/blob/7f9b7db482b8b1662b7466937e578008cbcb716e/client/ui/models/clientManagementModel.cpp). Это источник формата, не проверка вашего production clientsTable.

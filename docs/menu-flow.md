# GoVPN 6.71: выбор выхода и проверка исходящего IP

Review-ветка `fix/awg-warp-safe-persistence`, Draft PR #1. Main и рабочий VPS не менялись.

## Главное меню Amnezia

1. Клиенты - имена и маршруты.
2. WARP - подключение и восстановление.
3. Диагностика соединения.
4. Обслуживание - резервные копии и обновление.
5. Маршрутизация и резерв.

Группы разделены пустыми строками, шрифт без bold. Enter возвращает на предыдущий экран, в главном меню выходит; в списках клиентов обновляет данные. Номер и действие связаны одним массивом, видимые пункты всегда идут подряд.

Прежний главный пункт 6 «Восстановление AWG» убран: его название ошибочно обещало ремонт Amnezia. Восстановление только сохраненного WARP находится в **4 → 7**. Режимы без Amnezia перенумеровывают доступные пункты; команды CLI не менялись.

## Клиенты: только нужное в списке

Одна строка: номер, имя, IP, `[VPS]` или `[WARP]`. Метка - сохраненный выбор, не проверка интернета. Неизвестная политика обозначается `[?]`.

«Связь недавно» / «нет свежей связи» убраны. Это была эвристика по последнему обмену ключами за 180 секунд, не доказательство включенного/выключенного устройства. Из шапки также убрано число «активных» клиентов. Диагностика сохраняет явно подписанные сведения о последних обменах, когда они нужны для поиска ошибки.

Карточка содержит два действия: **1 - выбрать выход, 2 - изменить имя GoVPN**. Подробности handshake и техническое восстановление не мешают обычной работе. Создание/отзыв доступа, ключи и экспорт выполняются в приложении Amnezia; ранее сохраненные приватные файлы не удаляются.

Первое сообщение загрузки появляется до Docker. Все клиенты читаются одним exec с лимитом 6 секунд и исключением ключевых полей внутри контейнера. Ошибка не подменяется пустым списком и не применяет маршруты.

## Смена выхода: последовательный диалог

1. Карточка клиента открывает отдельный экран VPS/WARP с текущим выбором.
2. После выбора показывается отдельный экран проверки изменения: клиент, IP и прежний/новый выход.
3. Перед применением запрашивается подтверждение. Существенные ограничения WARP - внешний IPv4 DNS и общий запрет IPv6 AWG - показаны здесь один раз.
4. «Применяю выбранный выход» и «Проверяю сохраненный выбор» показывают этапы. Технический stdout контроллера не смешивается с меню.
5. Итог содержит клиент/выход/время. Успех показывается только после успешной команды и повторного чтения сохраненной политики. Интернет и Gemini этим шагом не объявляются проверенными.

Enter из выбора возвращает к карточке. Повторный выбор текущего выхода ничего не применяет и не запрашивает лишнее подтверждение. Отмена не меняет настройки. Ошибка применения или несоответствие прочитанной политики не получает зеленый итог. При выключенном WARP выбор для одного клиента не поднимает прежний список других клиентов; при включенном их маршруты сохраняются.

## WARP: польза отдельно от управления

Меню **2** определяет этап настройки. Пункт «Зачем нужен WARP - преимущества и ограничения» коротко объясняет дополнительный IP, шифрованный участок VPS -> Cloudflare и альтернативный путь. В основном диалоге не повторяются предупреждения про регион Google на каждом шаге.

Для Gemini, который работает через VPS, оставьте VPS: **1 → клиент → 1 → 1**. Преимущества WARP не означают гарантию доступа к конкретному сайту. [Описание и смысл восстановления](warp-purpose.md).

## Обслуживание и диагностика

В Amnezia режиме: 4 → 1 - backups, 2 - update, 3 - SSH план, 4 - зависимости, 5 - конфликты, 6 - перезапуск сервисов, 7 - восстановление сохраненного WARP, 8 - reboot, 9 - uninstall.

Раздел восстановления сначала читает состояние. Для остановленного контейнера показывает подготовку к следующему запуску без запуска; для работающего - повторное применение прежнего WARP. Оба действия требуют подтверждения. Отключенный/отсутствующий managed WARP не восстанавливается этим экраном; предлагается обычное меню 2. Клиентские ключи и регион Google здесь не исправляются.

**3 → 1** - общий отчет. **3 → 2** - отдельно подтверждаемые действия исправления. Отсутствие системного wgcf не является Fail работающего AWG: утилита нужна только для первой регистрации и загружается мастером приватно с checksum. Автоисправление пакетов использует фиксированный список, блокировку и повторную проверку; не переустанавливает Docker/Amnezia.

**5 → 1** - файл российских IPv4-сетей для импорта исключений в Amnezia; **5 → 2** - отдельный экспериментальный OpenFlux резерв. Эти функции и их ограничения не менялись: [инструкция](reserve-and-routing.md).

Проверки 6.70: 172 теста PASS в локальном Linux-контейнере без сети; macOS - 166 PASS, 6 skip. Новые проверки покрывают настоящий PTY диалог карточка/выбор/подтверждение/итог, отмену, noop, ошибку применения и сверки, сохранность остальных включенных клиентов и выбор одного клиента из выключенного WARP. Восстановление проверено для остановленного, работающего, отключенного и отсутствующего состояния. Backend WARP, OpenFlux и сетевые правила не перерабатывались; production VPS и Gemini не использовались.


В 6.71 **3 → 1** также сопоставляет исходный IP маршрута, внешний IP VPS, несколько публичных IPv4 и SSH-подсказку. Это предупреждение о неоднозначном выборе, не автоматическое исправление сети. При отсутствии части данных сравнение помечается неполным; HTTP 200 не скрывает несовпадение IP. Путь клиента и сохранение Docker NAT проверяются отдельно. См. [смена IP VPS](egress-ip.md).

# GoVPN 6.67: быстрые экраны и понятные этапы

Исправления по воспроизводимым замечаниям к 6.66 от 1 ноября 2026 года. Старые номера главного меню заменены намеренно; CLI команды сохранены. Main и production VPS не менялись.

## Навигация

Для Amnezia главное меню теперь идет по порядку:

1. Клиенты - профиль, доступ и маршрут.
2. WARP - подключение и восстановление.
3. Диагностика соединения.
4. Обслуживание.
5. Дополнительные функции.
6. Восстановление AWG после сбоя.

0 - выход. В других режимах недоступные действия не выводятся, остальные получают последовательные номера. Номер и действие берутся из одного массива; отображение больше не отделено от dispatch. Неоднозначные старые цифровые shortcuts удалены. Например, бывший пункт 3 больше не означает «клиенты»: теперь это диагностика.

Обслуживание: 1 - backups, 2 - update, 3 - подготовка SSH, 4 - зависимости, 5 - конфликты, 6 - перезапуск сервисов, 7 - reboot, 8 - uninstall. Сервисы имеют отдельный короткий список без пропущенных номеров. Обновление: **4 → 2**, подготовка SSH: **4 → 3**. Диагностика открывается без фонового опроса адресной книги; измерения запускаются только выбранным действием.

В карточке клиента: 1 - профиль/QR или инструкция восстановления, 2 - маршрут, 3 - имя, 4 - сохранение экспортированного .conf, 5 - legacy удаление. Проверка ключей выполняется перед выдачей, а не блокирует открытие карточки. Надпись «копия найдена» не равна проверке ее корректности.

## Почему мог надолго открываться список

До первого сообщения выполнялся Docker ps без timeout. Затем шли несколько отдельных Docker exec, лишняя проверка конфига и чтение WARP policy через Docker cp, даже когда WARP не настроен. Если один запрос переставал отвечать, экран не показывал, чего ждет.

Теперь экран загрузки появляется сразу. Получение имен контейнеров ограничено 6 секундами. Данные всех клиентов собираются одним Docker exec с общим лимитом 6 секунд, а не отдельным запросом на каждое имя. PrivateKey и PresharedKey исключаются внутри контейнера до передачи snapshot на хост. Для отображения policy читается только host state; отсутствие управляемого состояния обозначается неизвестным маршрутом, а не выдуманным прямым выходом.

Если AWG statistics недоступна, настроенные peers остаются видимыми, а handshake помечается как недоступный. Timeout возвращает понятную ошибку без применения сети и без подмены списка пустым. Лимиты относятся к каждому чтению, не ко всей длительной установке. Это ограничивает симптомы неответившего Docker, но не ремонтирует неисправный daemon на VPS.

## Единый WARP workflow

Вместо постоянного набора «тест / импорт / установка» сначала определяется этап:

- Нет профиля - первое действие «Подключить WARP»: создание отдельного account после согласия или импорт готового файла, затем выбор клиентов.
- Account найден, профиль не готов - «Продолжить настройку». Backend resume-only не имеет права зарегистрировать новый account, даже если прежний файл исчез.
- Профиль сохранен и выключен - включение прежнего профиля без регистрации.
- Прежняя legacy настройка - перенос сохраненного профиля и явный выбор клиентов, без необходимости создавать старый clients.list вручную.
- Настройки включены, но туннеля/правила нет - восстановление с проверкой инструментов до изменения маршрутов.
- Туннель и правило найдены - первое действие проверяет выход и при ошибке предлагает восстановить сохраненные настройки с подтверждением; само наличие интерфейса не называется рабочим интернетом или доступом к Gemini.
- Контейнер остановлен - сохраненное состояние можно подготовить без запуска. Если его нет, дается инструкция сначала запустить контейнер через Amnezia; первая регистрация из этого экрана не предлагается.

Замена профиля показывается как отдельное намеренное действие при уже существующей настройке. При первой установке импорт и создание профиля входят в один мастер. Тест и отключение не предлагаются как обычные действия для отсутствующего WARP. В combo сначала выбирается Amnezia или host WARP; один запуск не пытается скрыто настраивать оба сервиса.

Определение этапа - чтение с timeout. Это не health check Google и не доказательство Cloudflare handshake. Пакеты, профиль, маршруты и регистрации не меняются до явного выбора действия. Подтверждение нового account и списка клиентов остается обязательным.

## Старое обновление в уведомлении

В 6.66 баннер проверял только «версия отличается», поэтому кеш 6.65 выглядел обновлением. Теперь используется числовое сравнение major/minor/patch, отсутствующий patch равен нулю. Старый кеш не рекламируется; фоновая проверка более старой ветки тоже не возвращает устаревшее уведомление. Обычный updater по-прежнему запрещает downgrade без --force.

## Примеры и границы проверки

Из [angristan/wireguard-install](https://github.com/angristan/wireguard-install/blob/master/wireguard-install.sh) использован принцип разделения первой установки и управления существующим подключением. В [3x-ui](https://github.com/MHSanaei/3x-ui/blob/main/x-ui.sh) сверены приемы показа состояния установлен/остановлен/работает. Чужие installers не выполнялись, их небезопасные операции не переносились. Реализация GoVPN своя: единая нумерация и этапы собственного безопасного backend.

Добавлены проверки перехода из главного меню к 31 клиенту и обратно с настоящим Python backend и подставным Docker, ровно двух Docker запросов (ps + общий exec), timeout настоящего зависшего subprocess, всех режимов и этапов, старого кеша и resume-only. Локальный Linux Docker дополнительно проверяет общий snapshot, фильтрацию секретов до передачи, этапы WARP и прежний kernel packet-path набор. Production VPS, реальная регистрация Cloudflare и Gemini не использовались.


Проверки 6.67: 111 unit tests PASS в изолированном Linux, на macOS 107 PASS и 4 skip (настоящий flock/root installer). Kernel matrix и реальное чтение snapshot в локальном Docker прошли. Реальный зависший Docker daemon на VPS не диагностировался: воспроизведено ожидание зависшего subprocess и ограничен этот путь в приложении.

# GoVPN 6.69: компактное меню и отдельный резерв

Review-ветка `fix/awg-warp-safe-persistence`, Draft PR #1. Main и рабочий VPS не менялись.

## Основное меню Amnezia

1. Клиенты - имена и маршруты.
2. WARP - подключение и восстановление.

Проверка и обслуживание:

3. Диагностика соединения.
4. Обслуживание - резервные копии и обновление.

Дополнительно:

5. Маршрутизация и резерв.
6. Восстановление AWG после сбоя.

Обычный шрифт без bold; группы разделены пустыми строками. Голубой - заголовки/VPS, пурпурный - WARP, белый - подписи, желтый - номера/замечания, красный - опасные действия/ошибки. Цвет дублируется текстом.

Enter возвращает назад, в главном меню выходит. В списках клиентов Enter обновляет данные; в массовом выборе это не применяет несохраненные изменения. Поля ввода с явно указанным значением по умолчанию сохраняют свои правила. `0` - назад. Нумерация основных экранов генерируется из того же массива, по которому выполняется действие.

## Клиенты

Одна строка: номер, имя, IP, `[VPS]` / `[WARP]`, «связь недавно» / «нет свежей связи». Неизвестный маршрут обозначается `[?]`, статистика без ответа не называется отключением. Метка выхода отражает сохраненный выбор, не проверенный интернет. Подробности обмена ключами остаются в карточке.

Карточка: 1 - выход, 2 - имя GoVPN, 3 - сведения о связи. Создание/удаление peer, QR/конфиг и импорт клиентского ключа убраны. Доступ создается и выдается через приложение Amnezia. Ранее сохраненные приватные файлы не удаляются. [Подробнее](client-access.md).

Переход из главного меню читает терминал напрямую. Перед Docker сразу появляется сообщение загрузки. Контейнеры читаются с timeout 6 с, все клиенты - одним exec с лимитом 6 с и фильтрацией PrivateKey/PresharedKey до передачи. Ошибка не подменяется пустым списком. Шапка и групповое меню больше не выполняют неограниченные Docker запросы или скрытый запрос внешнего WARP IP. Эти ограничения не являются ремонтом неисправного Docker daemon.

## Диагностика и исправление

**3 → 1** - общий тест с этапами и итогом: VPS, DNS/TLS/HTTPS, AWG, выбранные маршруты, WARP fallback/защитные правила, IPv6. Проверка ничего не исправляет автоматически и не выполняет сторонние диагностические скрипты.

**3 → 2** - действия исправления. Доступны базовые зависимости и, только при включенной управляемой настройке, восстановление сохраненного WARP с подтверждением возможного перерыва. Регистрация нового аккаунта в этом действии не производится. Ошибка DNS, регион Google, блокировка IP и настройки телефона не объявляются автоматически исправляемыми.

**4 → 4** - обновленный экран зависимостей. Отсутствие системного wgcf не является ошибкой AWG/WARP. Он нужен лишь при первой регистрации и загружается мастером в приватный кеш с checksum. Системный wg-quick, qrencode, YAML и Reality scanner не проверяются как обязательные зависимости списка клиентов. WireGuard для WARP проверяется в правильном контейнере безопасным backend, не установкой поверх vendor AWG.

Исправление зависимостей после подтверждения устанавливает только недостающие пакеты из фиксированного списка, без eval, повторно проверяет команды и не печатает успех при неудаче. Docker и Amnezia не переустанавливаются этим действием. Нужен работающий Python менеджера; первоначальные зависимости перечислены в install.sh.

## WARP и Gemini

WARP сохраняет профиль автоматически, показывает нужное действие по текущему этапу и выводит фактический ход установки и итог. Ручной выбор файла в обычном меню отсутствует. Отключение не уничтожает учетные данные, повторное включение не регистрирует новый аккаунт.

Gemini проверяется на устройстве. На данном VPS он работает при выходе VPS и не работает через WARP: оставьте клиенту VPS (**1 → клиент → 1 → 1**) или отключите WARP в меню 2. Автоматической смены региона/аккаунта Google нет. Managed WARP по-прежнему блокирует весь IPv6 AWG; выбранным нужен внешний IPv4 DNS.

## Вместо установщика компонентов и прокси

**5 → 1** - подготовка российских IPv4-сетей для исключений в Amnezia. **5 → 2** - отдельный резерв OpenFlux. В Amnezia режиме больше нет MTProto, установки других VPN, Scanner и веб-компонентов. Уже установленные чужие сервисы не удаляются. В режиме существующего 3X-UI остаются его сеть и веб-обслуживание; новая установка протоколов скрыта.

Ограничения, хранение секретов, данные RIPE и первичные источники: [резерв и раздельная маршрутизация](reserve-and-routing.md). OpenFlux требует отдельного клиента и не обещает проход через любой белый список. IP-список страны не равен всем доменам `.ru`/`.рф` и требует импорта на самом устройстве.

Обновление **4 → 2** или `govpn update`, SSH план **4 → 3**. Технические CLI WARP и восстановление сохраненного состояния остаются. Подготовка SSH не изменяет sshd/firewall и не создает фактический независимый канал без второго доступного узла.

Проверки 6.69: 158 тестов PASS в одноразовом локальном Linux-контейнере без сети; macOS - 152 PASS, 6 skip для root installer/flock. Настоящий закрепленный OpenFlux core прошел make-link/parse-link и непривилегированный L4 запуск без сети, unit прошел systemd-analyze verify. Публичный ответ RIPE и экспорт проверены отдельно. Kernel matrix AWG/WARP проходила в 6.68; ее контроллер и runtime в этой итерации не менялись. Реальные captcha, клиентский импорт, операторские белые списки, Gemini и production VPS не тестировались.

# Gemini через Amnezia: что проверяет скрипт

GoVPN не является универсальным исправлением региональных ограничений Google. Одинаковая установка может дать разный результат на двух VPS с разными выходными адресами. Все исправления находятся в общем govpn.sh; разработчик не подключался к production VPS и не вносил индивидуальные серверные правки.

## Ошибка первого запуска в 6.64 и раньше

Сообщение «Сохраненный профиль WARP не найден» означает, что установка остановилась до применения WARP. Это не ответ Gemini. В прежних review-сборках до 6.65 переработанный безопасный путь WARP рассчитывал на существующий профиль; установка с нуля не была восстановлена. Импорт через меню также мог требовать несуществующий старый список клиентов. Это дефект первого запуска, устраненный в 6.65 отдельным bootstrap.

На новом сервере после обновления: **1 → 3 → 1** создает отдельный профиль через закрепленный wgcf после принятия условий Cloudflare. Затем выбираются конкретные клиенты. **1 → 3 → 2** использует готовый файл и тот же явный выбор. Сохраненные ключи другого VPS переносить для этого не требуется.

На уже настроенном сервере пункт **1 → 3** использует прежний профиль. Повторный setup не перерегистрирует аккаунт. Ошибка API, rate limit, недоступность GitHub/Cloudflare/package repositories или отсутствие kernel WireGuard остаются возможными причинами отказа; сообщение должно показывать этап, без ключей. До изменения routing выполняется preflight. Если позднее применение оказалось частичным, контейнер останавливается по fail-closed policy, см. runbook.

## Что покрыто на сервере

- Явно выбранные IPv4 /32 направляются через WARP; новые и невыбранные идут обычным путем VPS.
- При потере WARP interface/policy rule выбранные клиенты не переходят на прямой uplink. Существующий ruleset сохраняется вне собственных ресурсов.
- Managed WARP блокирует IPv6 ingress AWG целиком, включая доступ к серверным IPv6 resolver. Это защита внутри контейнера, не запрет IPv6 на телефоне.
- Профиль, список, исходный startup и account первой регистрации сохраняются приватно на хосте. Для restart и recreate условия различаются, см. [runbook](warp-safety.md).

## Что нужно проверить на клиенте

1. Для выбранного клиента задайте внешний IPv4 DNS, например `1.1.1.1`, в профиле/настройках подключения Amnezia. Старый DNS вида `172.x.x.254`, DNS самого AWG контейнера и другие локальные адреса могут быть заблокированы fail-closed правилами. Скрипт не редактирует конфиг на устройстве и не перенаправляет DNS прозрачно.
2. Если нужен полный туннель, маршруты клиента должны включать IPv4 и IPv6 (`0.0.0.0/0`, `::/0`), либо IPv6 должен быть отключен на устройстве. Исключенные приложения, домены и маршруты split tunnel сервер не видит и блокировать не может. Проверьте, что браузер/Gemini не исключен из VPN.
3. Переподключите VPN и перезапустите браузер/приложение после смены маршрута. Старые соединения могут сохранять прежнюю сессию.
4. На самом устройстве с включенным Amnezia откройте [Cloudflare trace](https://www.cloudflare.com/cdn-cgi/trace). Для выбранного клиента при работающем WARP ожидается `warp=on`/`plus`; `ip` показывает фактический выход этого запроса. Один этот запрос не доказывает отсутствие всех возможных утечек и не определяет решение Google о регионе.
5. Откройте Gemini на том же устройстве. Различайте отсутствие сети/DNS, HTTP ошибку и сообщение о регионе/аккаунте. Серверный curl и проверка через host SOCKS 40000 не заменяют этот шаг.

Если без WARP Gemini работает, допустимо оставить обычный выход VPS. Если через WARP сервис отказывает по региону, повторная установка того же профиля не гарантирует другого адреса или другого решения Google. Изменение только Endpoint не задает страну выхода.

У Gemini есть требования к местоположению, возрасту и типу аккаунта; доступность сайта и мобильного приложения может различаться. Проверяйте [условия входа Google](https://support.google.com/gemini/answer/13278668?hl=ru), [страны веб-версии](https://support.google.com/gemini/answer/13575153?hl=ru) и [доступность приложения](https://support.google.com/gemini/answer/14579026?hl=ru). Эти условия нельзя исправить только iptables.

## Проверки разработки

Первая установка проверяется с синтетическими account/profile и подставным wgcf: acceptance/отмена, явный список, SHA256, сохранение ключей, отказ API, повтор generate без регистрации и блокировка неопределенного повторного register. Локальный Docker отдельно проверяет bootstrap из готового синтетического профиля с настоящим kernel WireGuard preflight и маршрутизацию через dummy WARP. Реальные регистрация Cloudflare, его handshake, ваш образ и решение Gemini в эти результаты не входят.

## Для чего оставлять WARP

В этой схеме Amnezia уже шифрует участок устройство → VPS. WARP добавляет участок VPS → Cloudflare: сайты видят адрес выхода Cloudflare вместо обычного адреса VPS, а выбранный трафик идет дальше через другую сеть. Это может быть полезно, если у прямого выхода VPS плохая доступность конкретного ресурса или требуется разделить выходы клиентов. Улучшение маршрута/скорости нужно измерять, оно не гарантируется.

Цена - еще один туннель и зависимость от Cloudflare, дополнительная нагрузка/возможная потеря скорости, особенности DNS/IPv6 и другой выходной IP, который отдельный сервис тоже может отклонить. При fail-closed недоступность WARP означает потерю интернета для выбранных клиентов, а не незаметное переключение на прямой VPS.

WARP не обещает анонимность и выбор произвольной страны; эти ограничения отдельно указаны в [официальных режимах WARP](https://developers.cloudflare.com/warp-client/warp-modes/). Cloudflare также описывает возможное снижение throughput и несовместимость некоторых сервисов с геолокацией в [FAQ](https://developers.cloudflare.com/warp-client/known-issues-and-faq/). Это сведения об официальном клиенте; GoVPN использует отдельный WireGuard profile через wgcf, а не MASQUE-клиент со всеми его возможностями. Клиентские исключения официального приложения нельзя автоматически переносить на серверную схему.

Для владельца, у которого Gemini работает напрямую через VPS и не работает через WARP, разумный выбор - маршрут «через VPS» для этого клиента. Нет основания включать WARP всем только ради названия сервиса.

# Зачем WARP и что восстанавливают служебные пункты

## Практические преимущества работающего WARP

В GoVPN путь выглядит так: устройство -> Amnezia -> VPS -> WARP/Cloudflare -> сайт.

- Дополнительный выходной IP: сайт видит Cloudflare вместо публичного адреса VPS.
- Зашифрованный участок между VPS и Cloudflare. Участок устройства до VPS уже защищает Amnezia.
- Альтернативный сетевой путь к сайтам. Он может быть полезен, когда обычный выход VPS работает плохо; ускорение не гарантируется.

[Cloudflare FAQ](https://developers.cloudflare.com/warp-client/known-issues-and-faq/) описывает замену IP и возможное снижение пропускной способности. [Описание режимов](https://developers.cloudflare.com/warp-client/warp-modes/) объясняет путь через сеть Cloudflare и ограничения смены страны/анонимности. GoVPN использует WireGuard-профиль, а не официальный клиент MASQUE; свойства других режимов приложения автоматически на эту реализацию не переносятся.

Если обычный выход VPS уже дает нужный доступ, WARP может не принести практической пользы. По сообщению пользователя Gemini работает с выходом VPS и не работает с WARP: оставьте для него VPS. Это наблюдение не устанавливает точную причину отказа Google и не доказывает, что сам WARP недоступен для всех сайтов.

В этой реализации у выбранного клиента нужен внешний IPv4 DNS, а при включенном managed WARP весь IPv6 AWG блокируется. Отсутствие успешного выхода через WARP нельзя компенсировать обещанием другого региона. Выбор страны, исправление региона аккаунта и гарантированное ускорение не предлагаются.

## Что означали старые пункты восстановления

«Установить сохраненный hook в остановленный контейнер» записывает в startup-сценарий команду восстановления WARP перед обычным запуском AWG. Берутся прежние настройки и клиенты. Контейнер остается остановленным, новая регистрация не выполняется. Это нужно для предусмотренной остановленной фазы восстановления/пересоздания, а не для обычной смены выхода.

«Восстановить WARP в работающем контейнере» повторно применяет сохраненные интерфейс и правила WARP. Во время применения возможен перерыв; при частичной ошибке сохраняется защитное поведение. Клиентские ключи не восстанавливаются, регион Gemini не меняется. Если нет сохраненного включенного WARP, такое действие не предлагается.

В 6.70 общий пункт «Восстановление AWG» убран из главного меню и списка клиентов. Раздел **4 → 7 - Восстановление сохраненного WARP** показывает только одно действие, подходящее к текущему состоянию, с понятным описанием и подтверждением. Это не универсальный ремонт Amnezia.

## Как теперь выбирается выход

**1 → клиент → 1** открывает отдельный экран выбора. После выбора VPS/WARP показывается короткая проверка изменения: клиент, IP, прежний и новый выход, ограничения. Затем отдельное подтверждение, применение и сверка сохраненного выбора.

Ничего не меняется при отмене или повторном выборе текущего выхода. Другие включенные WARP-клиенты сохраняются. Если WARP был выключен, выбор WARP для одного клиента не включает его для всего прежнего сохраненного списка. Порядок сетевой защиты и глобальное ограничение IPv6 остаются прежними.

Фраза «выбор сохранен» означает подтвержденную запись настройки, не успешное открытие сайта. Диагностика интернета выполняется отдельно через меню 3. Технический stdout backend скрыт в этом диалоге; ошибки не превращаются в сообщение об успехе.
